# 智教 Harness 后续路线

状态：已确认（2026-10-21，MVP 改为对话，去掉点名、计时和投票）。MVP 已于 2026-10-22 标记完成。

前置文档：[MVP 路线](2026-10-21-mvp-roadmap.md)

本文排列 MVP 完成之后的阶段。MVP 是多轮对话，生产注册表为空。从本路线起，新能力登记为工具。图的节点、边和停机条件、四态任务保持不变。前一阶段的退出条件满足之前，不开始下一阶段。点名器、计时器、投票器和 `use_preset` 不在任何阶段里。

MVP 已于 2026-10-22 标记完成。

## 0. 当前决定（2026-10-22）

下一步做教师登录，从阶段三提前。网页、讲义、课堂编排不因此开始。阶段一和阶段二的进入条件不变。阶段三里的作品列表和 `compose_lesson` 仍等阶段二退出。设计见 [登录设计](2026-10-22-login-design.md)，已于 2026-10-22 确认。后端已实现。工作台尚未接上登录。

## 1. 排序原则

1. 先让对话稳定，再登记第一个会发布文件的工具。
2. 新工具使用 MVP 已预留的注册表。登记进同一张 LangGraph 图，不另建图，也不改节点和边。会发布文件的工具从阶段一开始共用「一轮一个候选、结束时发布」。
3. 只读工具可以在一轮里调用多次，只要最后仍只发布一个候选。会发布文件的工具共用同一个候选位。
4. 账号单独成阶段，并带数据迁移。不提前留空的属主列。
5. 队列和第二个模型替换执行器或适配层，不替换工具协议。
6. 第 6 节的项目在重新确认之前不进入任何阶段。

LangGraph 已是运行时，不是后续阶段。后续不替换这张图，不引入第二套编排，也不把检查点或 `interrupt` 加进来，除非某一阶段明确改写「教师补充后重新提交」这条规则。当前各阶段都仍是新任务，不恢复同一次 `invoke`。

## 2. 阶段一：第一个发布工具

### 进入条件

MVP 两步验收已通过。教师可以在同一会话里连续对话，生产注册表仍为空。

### 目标

模型通过登记进现有注册表的 `write_page` 发布一份自包含网页。不调用工具的一轮仍然只保存文字回复。不恢复点名器、计时器或投票器。

### 交付

- 登记 `write_page`。参数是 `title` 和 `files[]` 的 `path`、`content`。它调用校验器，通过则替换本轮候选。它不自己发布版本。
- 可以同时登记 `ask_teacher`。参数是 1 到 500 字的 `question`。调用后丢弃候选，本轮以 `failed` / `needs_clarification` 结束。
- 一轮最多一个候选。`invoke` 返回后，有候选才发布一个版本。失败不覆盖上一成功版本。
- 网页约束：入口 `index.html`；单文件不超过 500 KB，合计不超过 2 MB；UTF-8；相对路径；无外链脚本、外链样式和网络请求。后端不执行页面脚本。
- 预览用 iframe，`sandbox="allow-scripts"`，不授予 `allow-same-origin`。CSP 为 `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data: blob:; connect-src 'none'; base-uri 'none'; form-action 'none'`。
- 修改时，用户消息带上一版文件。模型调用 `write_page` 提交完整新文件。导出是该版本的 zip。
- 带页面正文的模型请求把 `max_tokens` 提高到能容纳文件。纯对话轮次仍用 2000。

### 不做

- 不实现点名器、计时器、投票器，也不新增 `use_preset` 或模板目录。
- 不引入可视化补丁编辑器。
- 不把 `write_page` 的输出自动收成模板。
- 不放宽外链、体积和沙箱限制。

### 退出条件

- 「做一个抽签决定哪一组先发言的转盘」由 `write_page` 发布，预览与导出的 `index.html` 一致。
- 只提问、不要求页面的一轮仍是文字回复，没有版本行。
- 校验失败只成为 `tool_result`。本轮没有候选时不发布。
- 把已发布页面改一处文案后，未提到的按钮还在。修改失败时，上一版本仍与修改前一致。
- 登记该工具时图的节点和边无改动。对话 MVP 的回归仍然通过。

## 3. 阶段二：讲义工具

### 进入条件

阶段一退出。网页发布没有已知的「失败覆盖成功版本」缺陷。

### 目标

教师要求讲义、阅读材料或活动说明时，模型调用新工具 `write_handout`，得到一份 Markdown。含糊的活动需求仍由模型调用 `write_page`。

选择 Markdown，是因为校验面是文本，预览在工作台里渲染，导出就是该文件。Word、PPT、Excel 不在这一阶段。

### 交付

- 登记 `write_handout`。参数是 `title` 和 `markdown`。输出 `index.md`，UTF-8，单文件，最大 200 KB。
- 新的 `artifact_type`：`handout`。一轮仍只有一个候选位。模型若先后调用了 `write_page` 和 `write_handout`，后一次校验通过的调用替换候选，工具结果里说明前一份候选已丢弃。系统提示词要求：教师同时要页面和讲义时调用 `ask_teacher`，不要在一轮里替换候选。
- 校验：路径合法、恰好一个 `index.md`、UTF-8、没有服务端指令、没有外链图片。不执行 Markdown 里的 HTML 脚本。
- 预览：工作台把 Markdown 渲染成只读视图，不把原始 HTML 插入页面。渲染器不执行脚本。
- 能力仍是 `preview`、`revise`、`export`。导出该版本的 `index.md` 和清单。
- 版本规则与网页相同。

### 不做

- 不做 `.docx`、`.pptx`、`.xlsx`。
- 不做讲义里的交互脚本。
- 不建第二张图或文档服务。

### 退出条件

- 「写一份十分钟的分数比较讲义」由 `write_handout` 发布，导出与该版本一致。
- 「做一个课堂计分板」仍由 `write_page` 发布网页，而不是讲义。
- 讲义校验失败只成为工具结果；本轮若没有其他候选，则没有版本行。
- 登记该工具时图的节点和边无改动。阶段一的网页回归仍然通过。

## 4. 阶段三：教师与课堂编排

### 进入条件

阶段二退出。网页和讲义共用候选位、发布和版本规则。

### 目标

一位教师登录后只能看到自己的任务和产物。模型可以调用 `compose_lesson`，把该教师已经发布的若干版本排成一页导航。

账号（注册、登录、退出）已在 2026-10-22 从本阶段提前，见第 0 节。本阶段剩下的是属主迁移、按属主过滤、作品列表和 `compose_lesson`。提前的登录若尚未包含属主，进入本阶段时再补迁移。

这一阶段改变信任边界。进入之前必须先有属主，再让多于一个人使用。

### 交付

- 账号：注册、登录、退出。口令只存哈希。会话标识只从环境配置的密钥签发。
- 迁移：任务和产物增加属主。已有无主数据归到一个明确的本地管理员账号。
- 每一次读取、预览和导出按属主过滤。工具执行时，只能把同一属主的已发布版本放进候选。
- 作品列表：标题、类型、最近版本、最近状态。
- 登记 `compose_lesson`。参数是有序的 `{artifact_id, version}` 列表，至少两项。它不让模型写新的互动脚本，只生成导航用的 `index.html`。`artifact_type` 为 `lesson`。
- 引用写死版本号。被引用产物以后有新版本时，课堂页保持原引用，除非教师再跑一轮并明确更新。
- 无权或版本不存在：工具结果失败，不替换候选。

### 不做

- 不做学校、班级名册和角色分级。
- 不做学生端实时同步。
- 不做公开分享链接。
- 不把登录状态传进 iframe 里的生成页。
- 不做子代理。课堂页不是另一张图。

### 退出条件

- 教师 A 不能读到教师 B 的任务、预览、导出，也不能把 B 的版本放进 `compose_lesson`。
- 课堂页按保存的顺序打开两个已有活动，打开的是指定版本。
- 被引用活动发布新版本后，课堂页仍打开旧版本，直到教师更新。
- 图的节点和边没有为 `compose_lesson` 改动。

## 5. 阶段四：生成变慢或上下文不够

三项彼此独立。默认顺序是检索工具、队列、第二个模型。若等待时间先成为问题，可以把队列提到检索前面，并在变更说明里写明原因。

### 5.1 检索工具

进入条件：阶段二已完成，且有明确的材料来源。没有材料时不登记这个工具。

交付：

- 登记只读工具 `search_materials`。参数是查询字符串。结果是若干段摘录，每段带来源标题和位置，合计不超过 6000 字。
- 它不替换候选，不发布文件。模型在同一步之后的 `write_page` 或 `write_handout` 里决定是否使用摘录。
- 材料的类型、大小和路径由该工具的实现读取配置好的资料目录。路径不来自模型输出，模型也不能把路径当成自由参数。
- 一轮的步数仍最多 6。检索占用一步。

不做：不建通用向量数据库平台，不做跨校语料库，不把检索写进系统提示词的固定段落。资料库选型到有材料时再定。

退出条件：一次讲义或网页的工具序列里出现 `search_materials`，随后发布的文件能看到来源名称。模型不调用该工具时，任务仍能只按教师原文完成。图的节点和边无改动。

### 5.2 后台任务队列

进入条件：进程内的 `invoke` 已经让 API 超时，或一轮时长稳定超过工作台可接受的等待。

交付：

- `GET /api/tasks/{task_id}` 的字段不变。
- 执行器换成队列消费者。状态仍以数据库为准。
- 消费者用任务 id 做幂等：已经是 `succeeded` 或 `failed` 的任务不再跑第二轮。
- 消费者崩溃时，规则与 MVP 的 `interrupted` 相同。

不做：不把队列变成工具或另一张图。不引入 Kubernetes。消费者调用的仍是同一张已编译的图。

退出条件：创建任务后 API 立即返回；消费者完成后仍是一轮一个版本；重复投递不会产生两个版本。

### 5.3 第二个模型

进入条件：有第二个可用供应商，并且第一个在工具调用上明显不够用。

交付：

- `complete(messages, tools)` 保持不变。配置里指定主模型和可选备用模型。
- 备用模型只在主模型超时或上游错误时，对同一步、同一组消息使用一次。
- 不按教师原文自动挑选模型。
- 日志记录配置名，不记录密钥和消息正文。

退出条件：主模型超时后，同一步能用备用模型返回工具调用；两个都失败时错误类别仍是 `model_timeout` 或 `model_upstream`。

## 6. 先不做

下面各项没有进入条件。重新确认之前，不建模块，也不在图的节点里写死分支。

| 项 | 保持在外的原因 | 若要重新打开，先写清 |
| --- | --- | --- |
| 随机点名器、课堂计时器、课堂投票器、`use_preset` | 已从产品范围删除。对话和开放式网页不依赖这三份模板 | 不恢复。若要类似互动，用 `write_page` 写新页面，并单独写校验和预览要求 |
| Word、Excel、PPT 全套生成 | 每种文件有独立的损坏判定。讲义工具只用 Markdown | 先做哪一种、如何校验、预览如何隔离 |
| 多 Agent、子代理 | MVP 只有一张图。第二个决策者会改写停机和发布责任 | 谁有权发布，失败时候选归谁 |
| 替换 LangGraph，或改用 DeepSeek Harness、LangChain Agent | LangGraph 已是运行时。`langchain-core` 只作为它的依赖存在。换成编程代理或 `create_agent` 会带入文件系统、Shell 或第二套状态 | 不开放 |
| 事件总线、插件热加载 | 注册表已经能加工具。热加载会让生产工具集合随请求变化 | 谁能登记工具，失败的插件如何不影响已发布版本 |
| 学生端实时课堂 | 需要房间、在线和权限 | 谁主持、断线后的计数以谁为准 |
| 学校组织、班级名册、权限分级 | 阶段三只有教师账号 | 一个教师属于多个班时产物归谁 |
| 在线发布市场 | 产物会离开作者的预览沙箱 | 审核、下架、作者与使用者的隔离 |
| 执行模型生成的 Shell、Python、SQL 或任意后端代码 | 与安全边界冲突 | 不开放 |
| 微服务、Kubernetes | 模块化单体覆盖到阶段四的队列 | 哪一个模块有独立扩容的证据 |
| 把 Redis 或 Celery 当作默认架构 | 阶段四之前在进程内 `invoke`。队列阶段可以选用它们来替换执行器，图本身不变 | 第 5.2 节的进入条件已经满足 |

## 7. 预留点

后续阶段只扩展这些接口：

- 同一张 LangGraph 图上的工具注册表，以及 `complete(messages, tools)` 的投影方式。
- 一轮一个候选、结束时发布、失败丢弃候选。
- 四态：`pending`、`running`、`succeeded`、`failed`。检索占用一步，不新增「检索中」。排队仍是 `pending`。
- 会话事件的四种类型。新工具不新增事件类型；工具名记在 `assistant_message` 和 `tool_result` 里。
- `/api` 前缀和统一错误正文。
- 网页预览用阶段一的 iframe 沙箱。讲义用工作台只读渲染。对话 MVP 不预览生成页。

## 8. 规范如何跟着阶段走

每个阶段开始时，只更新该阶段碰到的规则和本文的进入条件。不把检索或队列写进 MVP 规则里当作当前要求。LangGraph 已经是 MVP 的运行时，后续阶段不替换它。

`AGENTS.md` 第 3.2 节的后期清单仍然有效。某项移进当前阶段时，先改 `AGENTS.md` 再改代码。
