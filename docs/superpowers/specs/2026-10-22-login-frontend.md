# 登录工作台界面

状态：待实现（2026-10-22）

前置文档：[登录设计](2026-10-22-login-design.md)、[接口契约](../../api-contract.md)

本文只写工作台要呈现的状态、文案和请求。后端已经按登录设计实现。存储、密码哈希和 Cookie 签名不在本文。前端不保存密码，不读取 Cookie，不调用模型供应商。

沿用现在的侧栏、对话记录和输入框。不改品牌、不新增设置分区、不做注册以外的新页面。

## 1. 现有界面

这些文案还在，登录接上之后要换掉：

| 位置 | 现在 | 登录之后 |
| --- | --- | --- |
| 侧栏底部按钮 | 固定写「未登录」 | 未登录仍是「未登录」。已登录改为 `display_name` |
| 用户设置正文 | 「当前未登录。」 | 已登录时显示用户名、显示名和「退出」 |
| 侧栏会话列表 | `sessionStorage` 键 `zhijiao.conversations:v1` | 以 `GET /api/conversations` 为准 |

设置里的「外观」和「API/MCPs配置」保持原样。外观仍是「当前是浅色工作台。」

## 2. 三种画面

打开工作台先请求 `GET /api/auth/me`。在它返回之前，不发送消息，也不把账号名先写成「未登录」再改掉。账号位置写「正在确认登录…」。

### 2.1 未登录

主区域是登录表单，不显示对话记录，也不显示输入框。

- 标题：「登录」
- 字段：用户名、密码。密码框不回显明文。
- 主按钮：「登录」
- 切换：「没有账号？去注册」

切到注册后：

- 标题：「注册」
- 字段：用户名、密码、显示名。显示名可以留空。
- 主按钮：「注册」
- 切换：「已有账号？去登录」

侧栏「新对话」禁用。会话列表为空。底部按钮仍是「未登录」，点击后仍打开现有设置。用户设置正文写「请先登录。」不在设置里再放一套表单。

### 2.2 已登录

主区域回到现在的对话。输入框可以发送。侧栏底部按钮的文字是 `display_name`。

「新对话」恢复可用。会话列表用第 4 节的接口填充，最近的在上面。

用户设置：

- 标题仍是「用户设置」
- 一行显示名，用返回的 `display_name`
- 一行用户名，用返回的 `username`
- 按钮「退出」

退出完成前，这个按钮禁用，避免连点发出两次。

### 2.3 请求进行中

登录、注册、退出和打开页面时的 `GET /api/auth/me` 各自有等待。等待时对应按钮禁用。不另做全屏遮罩。

对话发送仍沿用现在的规则：上一条还在处理时不能再发送。

## 3. 字段

字数按 Unicode 码位计，和后端一致。提交前去掉用户名和显示名的首尾空白。密码不去掉空白。

| 字段 | 注册 | 登录 | 规则 |
| --- | --- | --- | --- |
| 用户名 | 必填 | 必填 | 1 到 32 个字，中间不能有空格 |
| 密码 | 必填 | 必填 | 8 到 128 个字 |
| 显示名 | 可空 | 不出现 | 留空则不传这个字段。填写时 1 到 32 个字，中间可以有空格 |

本地就能判断的错误，用下面的句子，不必等接口：

| 情况 | 句子 |
| --- | --- |
| 用户名不合法 | 用户名写成 1 到 32 个字，中间不要有空格。 |
| 密码不合法 | 密码写成 8 到 128 个字。 |
| 显示名填写了但不合法 | 显示名写成 1 到 32 个字。 |

接口返回的 `error.message` 直接显示。不要改写，也不要在后面追加堆栈、路径或密钥。

用户名 `local-admin` 由服务端拒绝。界面不必单独做提示，显示「这个用户名已经有人使用。」

## 4. 请求

所有 `/api` 请求都带上 Cookie：`credentials: "include"`。不要把 `zhijiao_session` 读进脚本，也不要放进 `localStorage` 或 `sessionStorage`。登录成功后浏览器会自己保存这枚 Cookie。

失败正文始终是：

```json
{
  "error": {
    "code": "invalid_input",
    "message": "用户名或密码不正确。",
    "retryable": false
  }
}
```

`code` 只用于判断要不要回到登录画面。展示给教师的是 `message`。

### 4.1 当前用户

`GET /api/auth/me`

已登录，200：

```json
{
  "user_id": "0123456789abcdef0123456789abcdef",
  "username": "teacher",
  "display_name": "王老师"
}
```

未登录，401，`message` 为「请先登录。」进入第 2.1 节，不把这句当成红色错误条。

网络失败时留在确认状态，显示「系统出错了，可以再发一次。」并提供重试。不要把它当成未登录。

### 4.2 登录

`POST /api/auth/login`

```json
{
  "username": "teacher",
  "password": "correct-horse"
}
```

200 的正文与第 4.1 节相同。成功后进入第 2.2 节，并请求会话列表。

用户名不存在或密码不对，都是 400，句子都是「用户名或密码不正确。」

### 4.3 注册

`POST /api/auth/register`

```json
{
  "username": "teacher",
  "password": "correct-horse",
  "display_name": "王 老师"
}
```

显示名留空时，请求里不要带 `display_name`。201 的正文与第 4.1 节相同。成功后同样进入已登录，并请求会话列表。

用户名已被占用时，409，句子是「这个用户名已经有人使用。」

### 4.4 退出

`POST /api/auth/logout`

不发送正文。204 没有正文。成功后清除页面上的会话列表和当前对话，回到第 2.1 节。

### 4.5 会话列表

`GET /api/conversations`

```json
{
  "conversations": [
    {
      "conversation_id": "0123456789abcdef0123456789abcdef",
      "title": "这节课怎么讲通分",
      "created_at": "2026-10-22T02:00:00Z"
    }
  ]
}
```

侧栏用 `title` 和 `conversation_id`。顺序保持接口返回的顺序，前端不再按标题排序。没有会话时，列表区域为空，不写额外说明。

标题由服务端生成：最早一条教师消息的第一行，超过 18 个字时保留前 18 个并加上 `…`。还没有消息时是「新对话」。前端可以继续用这个规则给刚创建、列表尚未刷新的一项临时标题，刷新后以接口为准。

登录、注册和退出之后，丢掉 `sessionStorage` 里的 `zhijiao.conversations:v1`。标题缓存如果还要留下，键改成 `zhijiao.conversations:v1:<user_id>`，并且每次进入已登录都先用本接口覆盖列表。

### 4.6 原来的对话接口

这些接口现在都要登录。成功时的字段不变。

| 动作 | 请求 |
| --- | --- |
| 新对话 | `POST /api/conversations`，201，正文只有 `conversation_id` |
| 发送 | `POST /api/conversations/{conversation_id}/messages`，正文 `{ "content": "..." }`，202 |
| 读取对话 | `GET /api/conversations/{conversation_id}` |
| 轮询 | `GET /api/tasks/{task_id}` |
| 读取模型配置 | `GET /api/llm/config` |
| 试连模型 | `POST /api/llm/probe` |

未登录调用它们时，401，句子「请先登录。」这时清空当前列表和对话，回到第 2.1 节。

别人的会话或任务是 404，句子「没有找到这个会话或任务。」把它从列表里去掉，主区域显示这句。不要写成「无权访问」。

上一条还在处理时，409，句子「上一条还在处理，请等它结束再发送。」

教师消息仍是去掉首尾空白后 1 到 4000 个字。不合法时显示「请把这句话写成 1 到 4000 字后再发送。」

## 5. 不要做

- 不在界面上解释哈希、Cookie 内容或 `AUTH_SECRET`。
- 不提供修改密码、修改显示名、注销账号。
- 不显示 `user_id`。
- 不把登录状态传进预览页。
- 不因为登录改对话气泡、输入框或设置里另外两个分区的版式。
