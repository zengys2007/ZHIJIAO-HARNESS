# 教学上下文与一键任务

状态：已确认（2026-11-01，用户提出「带上下文的备课与学情入口」）。本文把教师个人教学数据、学情洞察和一键式高频任务移入当前范围。

前置文档：[MVP 路线](2026-10-21-mvp-roadmap.md)、[后续路线](2026-10-21-later-roadmap.md)、[登录设计](2026-10-22-login-design.md)

## 0. 需求原文与解释

- 教师已有的教案、评分标准、班级名单、过往作业数据能被直接读取。
- 老师问「帮我分析这次单元测验」时，自动关联该班级近期作业记录与知识点图谱，直接输出薄弱点分布，不反问「请上传成绩表」。
- 高频任务（出题、写评语、做课件）封装为一键式入口，老师只需确认或微调。
- 做课件能力保留：产出的仍是课件内容（文字），由模型在对话里生成；不做 `.pptx` 文件（仍属后续路线「先不做」）。工作台界面不出现「写ppt」入口文案，一键入口叫「做课件」。

## 1. 范围

### 做

- 教学数据表（全部带 `owner_id`，按登录教师隔离）：
  - `classes` 班级、`students` 班级名单；
  - `knowledge_points` 知识点（名称、说明、先修知识点名单），构成图谱；
  - `assignments` 作业/测验（属于某班级），`scores` 每生每知识点的得分（0–100）；
  - `documents` 文档（`lesson_plan` 教案、`rubric` 评分标准，标题+正文）。
- API：创建班级/知识点/作业成绩/文档，读取总览与学情洞察。全部要求登录，只读写本人数据。
- 学情洞察（确定性计算，不依赖模型）：按班级聚合近期作业/测验，输出每个知识点的得分率、覆盖人次、与上一次的对比、薄弱点（得分率低于 0.7）排序；以及每位学生的知识点均分（供评语使用）。
- 模型上下文注入：一轮开始时，把该教师的教学上下文摘要（班级、名单、知识点图谱、近期作业、薄弱点分布、教案与评分标准摘录）作为一条附加 system 消息交给模型。摘要按 token 计入上下文窗口，不按 6000 字截断。放不进输入预算时先丢教案摘录，再丢学生名单，仍超则按 token 截断。无教学数据时不注入。
- 前端「备课与学情」视图：录入班级名单、知识点、作业成绩、教案/评分标准；展示薄弱点分布；提供一键示例数据。
- 一键任务入口：「出题」「写评语」「做课件」三个快捷按钮，按班级与薄弱点生成待发消息草稿，教师微调后发送。界面不出现「写ppt」字样。

### 不做

- 不做学校组织、跨教师共享、角色分级（「班级名册」仅指教师个人的教学班）。
- 不做 `.pptx`、`.docx`、`.xlsx` 文件生成。课件在对话里以内容形式产出。
- 不改 LangGraph 图的节点、边和停机条件；不登记工具；教学上下文注入发生在消息拼装层。
- 不做文件上传解析。录入用结构化表单或粘贴文本。
- 不做学生端、家长端或多人协作。

## 2. 数据与计算约定

- 得分一律 0–100 分。得分率 = 得分均值 / 100。
- 「近期」：该班级最近 5 次作业/测验；「上一次」：倒数第二次。
- 薄弱点：最近一次作业/测验中得分率 < 0.7 的知识点，升序排列；不足时补足得分率最低的前 3 个。
- 学生汇总：每生在近期各知识点的均分。
- 摘要摘录：教案/评分标准每份取前 500 字；学生名单每班最多列 30 个名字。总长度不设字数门。整段放不进本轮输入预算时，先删教案摘录，再删学生名单细节，仍超则按 token 截断。

## 3. 验收

1. 教师A录入的教学数据，教师B在 overview/insights 中不可见；B 的对话摘要也不含 A 的数据。
2. 录入示例数据后，在对话里问「帮我分析这次单元测验」，回复直接给出该班的薄弱点分布，且不出现「请上传成绩表」之类的要求。
3. 未录入任何教学数据的教师对话行为与改造前一致（不注入额外 system 消息，回归通过）。
4. 一键入口「出题/写评语/做课件」生成的草稿包含所选班级与薄弱知识点，教师可编辑后发送；界面不出现「写ppt」。
5. 现有对话 MVP、登录、工具调用的全部测试仍通过；图的节点和边无改动。
